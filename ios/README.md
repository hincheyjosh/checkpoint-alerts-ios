# Checkpoint Alerts — iOS

Native iOS (Swift/SwiftUI) port of the Android Checkpoint Alerts app, v1.0.
Same app, same data, same rules: it reads the official Tennessee Highway
Patrol monthly checkpoint PDF on tn.gov and warns you the day before and
the day a checkpoint happens in your area. Tennessee only for now.

## Features (mirrors Android v1.3.5)

- Official THP list only, current month + next month, fetched with browser
  headers (tn.gov blocks bare automated fetches). Sobriety and license
  checkpoints; seat-belt rows dropped. No times, THP doesn't release them.
- Same parser as Android, same checkpoint ids (including Java
  `String.hashCode` for the id suffix), so the two apps agree on the list.
- Alert scope: whole state, or my county + nearby counties (all 95 TN
  counties and their Census 2026 neighbors).
- Day-before and day-of warnings, one per checkpoint per day. Hourly
  reminders on checkpoint days, 7 AM-10 PM, one digest an hour, on by
  default. Both toggles in Settings; the list still refreshes with
  alerts off.
- JSON cache, so the list is never empty on launch; a failed refresh
  says so plainly and keeps showing last saved checkpoints.
- Footer on every screen: "Made with [leaf] in mind", the drawn green
  7-leaflet cannabis leaf from the Android app.

## How iOS differs from Android

- **Warnings are scheduled ahead.** iOS background work is best-effort,
  the system decides when the daily check runs and it may not run every
  day. So the app schedules its day-before and day-of warnings as local
  notifications at 8 AM on the warning day, and rebuilds that schedule
  on every launch and refresh. If you open the app after 8 AM and a
  warning is still owed, it goes out right away instead.
- **Hourly reminders are scheduled ahead too**, one local notification
  per hour, 7 AM-10 PM, for today and tomorrow, rebuilt on every launch
  and refresh.
- **No battery settings section.** iOS has no battery-optimization
  exemption to set. Settings has a "Background refresh" section instead,
  with a button to the system Settings, where Background App Refresh
  lives.
- **No Android-style background worker.** The daily check runs through
  `BGAppRefreshTask` (Background Modes: fetch + processing). It is
  best-effort, which is why the warnings are scheduled ahead.

## Building on a Mac

Requires Xcode 16 and iOS 16 or later.

```sh
# Generate the app icons (they are build artifacts, not committed)
python3 -m pip install pillow
python3 ios/Scripts/generate-icons.py

open ios/CheckpointAlerts.xcodeproj
```

Pick your development team in the project settings (Signing &
Capabilities), then build and run. The project is generated by
`ios/Scripts/generate-project.py`, re-run it after adding or removing
source files.

Unit tests: `xcodebuild test -project ios/CheckpointAlerts.xcodeproj
-scheme CheckpointAlerts -destination 'platform=iOS Simulator,name=iPhone 16,OS=latest'`.
They cover the THP parser (including the real November 2026 PDF text),
the day-before/day-of selection, the hourly gates, and the county scope.

## Getting it on a real iPhone

A Mac build alone does not put the app on a phone. You need:

1. An **Apple Developer Program** membership, $99 a year, under your
   Apple ID. Enroll at developer.apple.com.
2. In Xcode, sign in with that Apple ID and pick your team for the
   Checkpoint Alerts target. The bundle id is `com.checkpointalerts.app`.
3. **TestFlight** for testing: archive the app, upload to App Store
   Connect, and invite testers. Or submit to the **App Store** for
   everyone.

The app collects nothing. The privacy policy in the repo root
(`PRIVACY.md`) covers it.
